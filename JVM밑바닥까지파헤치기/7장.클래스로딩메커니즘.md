# 7.1 들어가며
- 클래스 파일에 서술된 정보를 가상머신이 이용하려면 메모리에 로드해야 한다.
- 로딩 방법과 로딩된 클래스를 JVM 안에서 활용하는 방법을 이번 장에서 소개한다.
- 클래스 로딩 메커니즘이란, 클래스 데이터를 IO로 부터 메모리로 읽어들인 뒤 데이터를 검증, 변환, 초기화해서 가상머신이 사용할 수 있는 자바 타입을 생성하는 과정이다.
- 자바에서는 클래스 로딩, 링킹, 초기화가 모두 런타임에서 일어나므로 실행 성능이 떨어진다. 하지만 유연성을 확보할 수 있다는 장점이 있다.
- 클래스 로더를 이용해 실행 중인 프로그램의 코드 일부를 네트워크를 통해 바이너리 스트림으로 읽어올 수 있다.

# 7.2 클래스 로딩 시점
- 타입의 생애 주기는 로딩 -> 검증 -> 준비 -> 해석 -> 초기화 -> 사용 -> 언로딩 이다.
- 검증, 준비, 해석을 링킹이라고 한다.
- 로딩, 검증, 준비, 초기화, 언로딩은 반드시 순서대로 시작해야 한다.
    - 여러개를 동시에 시작해서 병렬적으로 처리할 수 있다.
- 초기화는 즉시 시작되어야 하는 상황이 여섯가지 있다. (여섯가지 뿐)
    - new, getstatic, putstatic, invokestatic을 만났을 때
        - 인스턴스 생성이나, 정적 필드 읽거나 생성, 정적 메서드 호출등을 의미한다.
    - 리플렉션 메서드를 사용할 때 해당 타입이 아직 초기화되어 있지 않은 경우
    - 클래스를 초기화할 때 상위 클래스가 초기화되어 있지 않은 경우
    - 메인 메서드 실행하는 경우
    - REF_getStatic, REF_putStatic, REF_invokeStatic, REF_newInvokeSpecial 타입 메서드 핸들을 해석해 얻은 MethodHandle 인스턴스를 호출할 때 초기화되어 있지 않은 경우
    - 인터페이스에 디폴트 메서드를 정의했으나, 구현체가 초기화될 때 인터페이스가 초기화되어 있지 않은 경우
- 능동 참조는 타입 초기화를 일으키는 참조이고, 수동 참조는 그렇지 않은 참조이다.
    - 예를 들어 하위 클래스로 상위 클래스의 static 변수를 읽는다면 상위 클래스의 getstatic 명령어가 실행되어 상위 클래스가 초기화되지만, 하위 클래스는 초기화되지 않는다.
- 배열은 JVM이 배열을 뜻하는 클래스를 자동으로 만드므로, new 키워드로 배열을 생성한다고 해서 배열 원소 클래스가 초기화되지는 않는다.
- A 클래스에서 B 클래스의 상수를 참조해도, 상수 전파 최적화가 된 경우, 참조되는 상수는 A 클래스의 상수 풀에 저장되므로 B 클래스는 초기화되지 않는다.
- 상위 인터페이스 초기화는 상위 인터페이스가 실제로 사용될 때 (인터페이스에 정의된 상수 참조) 이루어진다.

# 7.3 클래스 로딩 처리 과정
- 로딩 단계
    - 이름으로 클래스를 정의하는 바이트 스트림을 가져온다. (파일 or 네트워크 등등)
    - 바이트 스트림을 메서드 영역에서 사용하는 런타임 데이터 구조로 변환한다.
    - 로딩 대상 클래스를 표현하는 Class 객체를 힙 메모리에 로딩한다. (이 클래스 객체로 메서드 영역에 저장된 타입 데이터를 활용할 수 있다.)
    - ClassLoader의 findClass 또는 loadClass를 오버라이딩하면 바이트 스트림을 얻는 방법을 통제할 수 있다.
- 검증 단계
    - 클래스 바이너리는 컴파일러가 아닌 임의의 방법으로 생성할 수 있으므로 검증 단계가 필요하다.
    - 파일 형식 검증
        - 패직 넘버로 시작하는가 등 파일의 형식을 검증한다.
        - 바이트 스트림을 대상으로 검증하며, 이 검증을 통과하면 메서드 영역에 저장된다. 이 후 단계는 메서드 영역을 참조한다.
    - 메타데이터 검증
        - 상위 클래스가 상속을 허용하는지 등 자바 문법관련된 내용을 검증한다.
    - 바이트코드 검증
        - 위 단계에서는 타입에 대한 검증을 했고, 바이트 코드 검증은 메서드 본문에 대한 검증을 한다.
        - 점프 인스트럭션이 메서드 외부 바이트코드로 점프하는 지 등
    - 심벌 참조 검증
        - 심벌을 직접 참조로 바꿀 때 외부 자원이 존재하는지, 그리고 권한이 있는지 검증한다.
    - 검증 단계는 중요하지만 필수는 아니기 때문에 -Xverify:none으로 검증을 건너뛸 수 있다.
- 준비 단계
    - static 변수를 메모리에 할당하고 초깃값을 설정하는 과정이다.
    - static 변수에 할당하는 값은 해당 데이터 타입의 제로값이다.
- 해석 단계
    - 해석은 심벌 참조를 직접 참조로 대체하는 과정이다.
    - 클래스 또는 인터페이스 해석
        - 클래스 로더가 로딩하면서 메타 데이터 검증과 바이트코드 검증이 되므로 로딩이 되면 유효한 타입이란 거고, 접근 권한 체크도 이루어진다.
    - 필드 해석
        - 필드 해석 또한 상위 클래스를 재귀적으로 검색한다.
    - 메서드 해석
        - 필드 해석과 마찬가지로 재귀적으로 해석한다.
    - 인터페이스 매서드 해석
        - 인터페이스 테이블을 찾고, 상위 인터페이스들에서 재귀적으로 찾는다.
- 초기화 단계
    - static 한 필드들을 초기화하고, static 블록 코드를 수행하는 단계이다.

7.4 클래스 로더
- 클래스는 클래스 이름과 클래스를 로딩한 클래스 로더로 식별된다.
- 클래스는 부모 위임 모델을 따른다.
    - 범용적인 클래스일 수록 상위의 클래스 로더가 로드한다.
    - 범용 클래스를 하위의 클래스 로더가 각자 로드하여 타입 시스템이 망가지는 것을 방지한다.
- JNDI, JDBC와 같이 예외 케이스도 존재한다.
